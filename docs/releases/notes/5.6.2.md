# Version 5.6.2

## Changes
- Fixed multiple issues with type inference and type handling
- Updated README with improved documentation and configuration instructions
- Fixed bug with empty string configuration not returning default values
- Improved date/time parsing and millisecond discovery
- Removed support for map output types in favor of records for better datalake querying

## Technical Details

### Type Handling Improvements
- Fixed map output type support in favor of record types for better compatibility
- Improved array schema handling to ensure consistent type validation
- Fixed boolean inference from integers and strings
- Enhanced date and time field parsing for more accurate discovery

### Configuration Enhancements
- Fixed critical bug where empty string configuration values weren't returning defaults
- Improved configuration validation and fallback mechanisms
- Enhanced environment variable handling for better reliability

### Documentation Updates
- Completely redesigned README with clearer structure and examples
- Added comprehensive configuration documentation
- Simplified setup instructions for various platforms
- Included examples for basic usage scenarios

### Bug Fixes
- Fixed millisecond timestamp discovery for better time handling
- Fixed tests to reflect new array of records structure instead of maps
- Fixed type inference for arrays to ensure correct schema validation
- Improved schema compatibility with data warehouse systems

### Schema Evolution Updates
- Updated schema evolution to use records instead of maps for better queryability in datalake
- Fixed buggy behavior associated with map types

### Technical Details
- Modified `src/discover/evolution.rs` to:
  - Update field evolution tests to expect record types instead of map types
  - Ensure consistent value types in schema evolution
  - Improve validation of evolved field metadata
  - Maintain backward compatibility with existing string fields

### Impact
This change improves data queryability in datalake environments by using record types instead of maps. While this is a breaking change in terms of schema evolution behavior, it provides better reliability and query performance. Existing string fields remain unchanged, and only new evolutions will use the record type.
