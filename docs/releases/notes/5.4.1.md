# Version 5.4.1

## Changes
- Implemented highwatermark S3 list continuation token for improved performance
- Added offset database rollup for S3 input plugin
- Fixed handling of deadlettered messages
- Improved handling of schema synchronization
- Enhanced CI/CD pipeline with new tests

## Technical Details

### Performance Improvements
- Reduced latency when ingesting BAU data by storing highwatermark of last ingested object key
- Implemented S3 list continuation token to avoid scanning the entire bucket on each sync
- Optimized offset handling by relying on the WAL for most cases, reducing Offset DB I/O overhead
- Added offset database rollup to prevent indefinite growth for S3 input plugin

### Offset Management
- Fixed critical issue with deadletter messages by committing their offsets
- Ensured deadlettered messages are not re-ingested on restart when at the head of the source data stream
- Implemented vacuum operations for offset database maintenance
- Added safeguards to ensure Offset DB only increments offset position values for existing keys

### Schema Management
- Made schema synchronization conditional on output configuration
- Improved support for local development without impacting destination systems
- Enhanced metadata API error handling to prevent schema inconsistencies
- Required successful metadata API requests to maintain consistency between Skippr API, ingested data, and destination schema

### CI/CD Enhancements
- Added new end-to-end tests for offset database rollup
- Implemented event types testing for more comprehensive validation
- Optimized CI/CD pipeline for ARM64 and x86 builds
- Added chaos mode testing to ensure resilience
