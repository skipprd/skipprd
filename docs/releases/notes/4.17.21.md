# Version 4.17.21

## Changes

### Buffer Management Improvements
- Converted buffer operations from synchronous to asynchronous
- Implemented an in-memory buffer index for improved performance
- Enhanced file handling with async tokio operations
- Improved buffer file tracking with consistent file references

### File I/O Enhancements
- Moved from std::fs to tokio::fs for asynchronous file operations
- Enhanced file writing with async operations for better performance
- Improved file descriptor management with optional wrapping
- Added path tracking to output files for better file management

### Concurrency Improvements
- Added buffer index data structure for better concurrent access
- Implemented file descriptor caching to reduce open file handles
- Enhanced buffer management with tokio async runtime
- Added proper file locking mechanisms for concurrent operations

## Technical Details
- Added `BUFFER_INDEX` static variable with DashMap for concurrent file tracking
- Modified `OutputFile` structure to use optional tokio::fs::File and include path
- Implemented `build_buffer_index` function to initialize the buffer index
- Converted all file operations to use tokio's async I/O functions
- Added proper buffer creation and management for concurrent operations
- Updated rotation and finalization processes to use async operations
- Modified main.rs to build buffer index on startup
- Enhanced ingest process to use the buffer index for file operations

## Impact
This release significantly improves system performance and reliability by implementing asynchronous file I/O operations. The addition of an in-memory buffer index reduces file system operations and enables better concurrent access to buffer files. These changes enhance throughput and reduce contention when multiple threads access the same files, resulting in more efficient data processing and better resource utilization. The improved file descriptor management also reduces the risk of exhausting file handles in high-volume scenarios.
